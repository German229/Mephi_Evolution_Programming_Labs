# ЛР4. Заявка на проект

**Тема (вариант 5):** эволюционный поиск формул для символьной регрессии с контролем разрастания деревьев (bloat).

## 1. Постановка
Дана выборка $\{(\mathbf{x}_j, y_j)\}$, где $y = g(\mathbf{x}) + \varepsilon$ и функция $g$ неизвестна. Нужно найти выражение $h$ из языка $\mathcal{L}$, которое
- минимизирует ошибку на отложенной выборке (NRMSE на test);
- при этом остаётся компактным: размер дерева (число узлов) — второй критерий качества модели.

*Bloat* — рост размера деревьев без улучшения ошибки. Он замедляет поиск, ухудшает интерпретируемость и способствует переобучению. **Исследовательский вопрос:** какой механизм контроля разрастания даёт лучший компромисс между точностью, размером и временем при равном бюджете вычислений?

## 2. Представление
- **Особь** — синтаксическое дерево, хранящееся как префиксный список токенов. Генотип совпадает с деревом, фенотип — функция $h(\mathbf{x})$.
- **Функции:** $+,\ -,\ \times,\ \div_{\text{prot}},\ \sin,\ \cos,\ \exp_{\text{prot}},\ \log_{\text{prot}}$. Защищённые версии определены везде: $\div_{\text{prot}}(a, 0) = 1$, $\log_{\text{prot}}(a) = \log|a|$, $\log_{\text{prot}}(0) = 0$, у $\exp_{\text{prot}}$ аргумент ограничивается сверху.
- **Терминалы:** переменные $x_i$ и эфемерные константы из $U(-1, 1)$.
- **Синтаксическая корректность** гарантирована по построению: операторы заменяют только целые поддеревья.

## 3. Алгоритм (всё реализуется самостоятельно)
Поколенческое ГП:
- инициализация ramped half-and-half;
- турнир;
- кроссовер поддеревьев (90 %);
- мутация поддерева или точечная мутация;
- элитизм;
- линейное масштабирование выхода $a + b\,h(\mathbf{x})$ (Keijzer, 2003) — дешёвый способ убрать зависимость от масштаба.

**Сравниваемые механизмы контроля разрастания** (одинаковый бюджет):

| вариант | механизм |
|---|---|
| **A. Базовый** | только жёсткий предел глубины (17, по Козе) — эталон, на котором видно разрастание |
| **B. Парсимония** | штраф $F = \text{NRMSE} + c \cdot \text{size}$ |
| **C. Тарпейский метод** | особь крупнее среднего размера популяции с вероятностью $p$ получает худший фитнес без вычисления (Poli, 2003) |
| **D. Многокритериальный** | собственный NSGA-II по паре (ошибка, размер) из ядра `evo_core/moo.py` (ЛР3) |

## 4. Данные и симулятор
Синтетические эталонные задачи символьной регрессии с фиксированным seed:
1. **Nguyen-7:** $\ln(x+1) + \ln(x^2+1)$, $x \in [0, 2]$.
2. **Pagie-1** (2 переменные): $\frac{1}{1+x^{-4}} + \frac{1}{1+y^{-4}}$, $x, y \in [-5, 5]$.

Шум $\varepsilon \sim N(0, (0.05\,\sigma_y)^2)$. Разбиение: train 60 %, validation 20 % (выбор итоговой модели), test 20 %. Дополнительно проверяется экстраполяция за пределы обучающего интервала.

## 5. Критерии оценки и методика
- **Бюджет:** одинаковый во всех вариантах — 20 000 оценок деревьев на запуск (популяция 200 × 100 поколений). Дополнительно учитывается суммарное число вычисленных узлов как честная мера стоимости.
- **Серии:** **30 независимых запусков** на вариант и задачу (seed задаётся через CLI).
- **Метрики:** NRMSE на test, размер и глубина итоговой модели, динамика среднего размера по поколениям, время.
- **Статистика:** медиана и IQR, U-тест Манна—Уитни с поправкой Холма на множественные сравнения, размер эффекта $\hat A_{12}$ Варги—Делани.
- **Визуализации:**
  - динамика ошибки и размера по поколениям (полоса по 30 запускам);
  - диаграмма «ошибка — размер» для всех вариантов;
  - фронт Парето варианта D;
  - графики аппроксимации и экстраполяции;
  - три эволюционировавших формулы разной сложности.

## 6. Ожидаемые риски
| риск | мера |
|---|---|
| Разрастание в варианте A замедлит серии на слабой машине | предел глубины и размера (500 узлов); компиляция дерева в одно numpy-выражение с кэшем по строке; при необходимости уменьшить популяцию |
| Численные особенности (деление на 0, переполнение exp) | защищённые операции, `nan`/`inf` → худший фитнес |
| Переобучение на шум | отдельная validation-выборка для выбора модели, отчёт по test |
| Нечестное сравнение (C экономит вычисления, D меняет отбор) | одинаковый бюджет оценок и отдельный учёт числа вычисленных узлов |
| Чувствительность B к коэффициенту $c$ | $c$ подбирается на отдельных seed, отличных от итоговых |

**Оценка вычислений:** 4 варианта × 2 задачи × 30 запусков ≈ 240 запусков по ~1–3 с, то есть ~5–10 минут на полный набор (серия одного варианта — 1–1.5 мин).
